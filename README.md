# Mini-World Synthetic Dataset Generator

A small, deterministic TypeScript generator that produces a controlled synthetic
text dataset (`data/mini-world.txt`) for training the small GPT model from
Sebastian Raschka's *LLM From Scratch*.

The dataset is a "mini world" with ~100 meaningful words and stable semantic
relationships (`cat ↔ fish`, `dog ↔ meat`, `car ↔ road`, `john ↔ cat`, ...),
expressed through many different sentence templates. This makes it easy to
inspect embeddings, attention, and next-token predictions after training —
the resulting file is intended to replace `the-verdict.txt` in the training
notebook.

No LLM APIs, no external datasets. Pure seeded generation.

## Usage

Requires Node.js >= 22.18 (runs TypeScript natively; no build step).

```bash
npm install
npm run generate
```

Configurable:

```bash
npm run generate -- --words 40000 --seed 123
npm run generate -- --tokens 50000        # converted to ~40000 words
npm run generate -- --out /some/dir       # output directory (default: ./data)
```

Generation is deterministic: the same `--seed` always produces byte-identical
output.

## Outputs

- `data/mini-world.txt` — plain UTF-8 text, one sentence per line,
  multi-sentence stories separated by blank lines.
- `data/mini-world-stats.json` — seed, sentence/word counts, unique word count,
  per-category chunk counts, and word frequencies.

Default target is 40,000 whitespace-separated words ≈ 50,000 GPT-2 BPE tokens.
The Python training notebook can report the exact `tiktoken` count.

## Dataset composition

| Category                       | Share |
| ------------------------------ | ----- |
| Animal relationships           | 25%   |
| People + possession            | 20%   |
| Vehicles                       | 15%   |
| Places / objects               | 15%   |
| Short multi-sentence stories   | 15%   |
| Mixed concepts                 | 10%   |

Chunks are generated by weighted random selection and shuffled, so sentences
are never grouped by concept.

Semantic relationships are fixed in `src/relationships.ts` (e.g. cat→fish,
dog→meat, bird→seeds, boat→water, car→road, train→railway, john→cat,
mary→dog, bob→car). Templates only ever combine words through these
relationships — you will never see "the cat eats gasoline". The same
relationship appears in many surface forms:

```text
the cat eats fish.
a cat likes fish.
fish is food for the cat.
john gives fish to his cat.
the cat eats fish in the kitchen.
```

## Structure

```text
src/
├── vocabulary.ts     word lists / categories (~100 meaningful words)
├── relationships.ts  cat→fish, dog→meat, car→road, john→cat, ...
├── templates.ts      sentence/story patterns per category
├── random.ts         seeded PRNG (mulberry32)
├── generator.ts      dataset creation, stats, validation
└── index.ts          CLI
test/
└── generator.test.ts
```

## Tests & typecheck

```bash
npm test         # node:test — determinism, word target, relationship
                 # consistency, vocabulary bounds, file output, no
                 # undefined/null strings, template validity
npm run typecheck
```

Generation also self-validates: it throws if the word target is not met, if
`undefined`/`null`/`NaN` appears in the text, or if a line is not a
period-terminated sentence, and warns if unique words fall outside 50–150.
